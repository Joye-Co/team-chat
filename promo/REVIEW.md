# 交付说明

1920×1080，60 fps，84.2 秒。中文成片是 `out/promo-1080p60.mp4`，英文成片是 `out/promo-1080p60-en.mp4`，
各有一个 `-small` 小体积版（落地页用的就是小体积版）。
为什么这样做见 [STORYLINES.md](STORYLINES.md)，规格和逐镜头表见 [SPEC.md](SPEC.md)。

## 配乐

《Be Happy》（Michael Ramir C.，Mixkit），120 BPM，大调。同一部片子按三首曲目各剪过一版，
听过三版之后选定了这一首（2026-11-12）；另外两首是《New York》和《Close Up》。

片子怎么卡它：批准合并落在第 12 小节；成员页落在第 28 小节的起势上；功能段的最后几个镜头和那句结论
压在 4 小节的间奏上；整屏变黑落在最后一段副歌的第一拍；图标落在第 38 小节；点下「预约」落在结尾和弦上。

授权允许商用和线上宣传，无需署名，但**不含电视和广播投放**（见 [out/CREDITS.md](out/CREDITS.md)）。

## 配乐是怎么选的

上一首不行，而做片子的 agent 听不到声音，所以不再只凭标签挑：

1. **先量参考片。** 把 Cowork、Kimi、Cursor、Notion 四支发布片的音轨拿来测量。它们的共同点：100–115 BPM 的稳定
   四拍律动，低频（鼓和贝斯）占大头，响度有明显的铺垫和爆发。上一首《Wingspan》是 82 BPM，几乎没有低频，
   高频发闷，全程响度不变：一首抒情的原声底乐，不是发布片的配乐。
2. **再量候选。** 从 Mixkit 下载了 220 首电子、放克、合成器流行、企业配乐类的曲目，逐首测量速度、鼓点密度、
   明亮度、动态，筛到 30 首后再分析每首的小节结构、调性、结尾方式，以及整体音色和参考片的距离。
3. **按结构选出三首，交给人听。** 三首都是大调、律动清楚，段落变化的位置能和片子的关键时刻对上；
   各剪一版完整的片子，听过之后再挑定。
4. **让片子去卡音乐。** 片子按「拍」写成，时间表（`timing/be-happy.json`）把点击、整屏变黑、图标落下、
   点下「预约」这几拍绑到曲目的小节线上。小节线的位置是直接量波形得到的，卡点误差在 20 毫秒以内。
5. **只剪一刀。** 为了让音乐和片子一起自然结束，去掉了第 40–43 小节，结尾和弦正好落在点下「预约」上；
   剪接处前后两小节的音色和和声测过是相近的。

## 英文版

同一部片子、同一首配乐、同样的卡点，文字和界面换成英文：

- **界面是英文的。** 后半段的真实截图换成落地页的英文截图（桌面端截图自测 `--lang en` 画的）；首页「刚处理」和
  月报 v2 这两张落地页没有，用同一个自测补拍，顺手把自测翻译表里缺的 8 句英文补上了。故事段重建的话题界面
  用的也是自测翻译表里的说法（小王是 Will，陈晨是 Chloe，「开发」群是 Engineering）。
- **英文界面的位置不一样。** 英文版右侧面板从 x=1040 开始，按钮更宽，所以首页、月报、交还、⌘K、六张卡片上的
  按钮和被盖住的区域都按英文截图重新量过（`film.js` 的 `GEO`）；⌘K 的句子按每个字母的右边缘逐个露出。
- **片子自己的话是按英文写的，不是翻译。** 口径对齐英文落地页：结尾一句是 "Your team and every agent, /
  on the same page."，定位句用落地页标题 "Team chat where AI agents are teammates."，按钮是 "Get early access"。
- **字体用 SF。** 无头浏览器认不出 `-apple-system`，会用苹方的拉丁字形排英文（连字符都变形），英文版按文件
  加载系统的 SF Pro 和 SF Mono；英文单词不在中间断行；英文句子更长，逐字出现的间隔减半，出现时长和中文相当。
- 响度和中文版一样（-16.5 LUFS，峰值 -1.7 dBFS），抽帧和关键时刻的静帧都看过。

## 落地页

两个落地页（`/` 和 `/en`）在首屏标题和按钮下面各嵌了自己语言的版本：海报是「方案对比」那一刻，中间一个
「看宣传片 1:24」按钮，点了才加载、带声音播放，滚出视野会暂停。视频和海报带着私有的角色形象，**不进仓库**：
放在 `~/.config/team-chat/website/media/`（`film-zh.mp4`、`film-zh.jpg`、`film-en.mp4`、`film-en.jpg`），
`apps/website/build.ts` 构建时拷进 `dist/media/`；没有这些文件时，页面上不出现这一块。

## 量过的、看过的、听过的

- 量过：四支参考片和 220 首候选的音频特征；曲目的精确速度和每个卡点处鼓点的时间；剪接处的相似度；
  成片响度（-16.5 LUFS，峰值 -1.7 dBFS）；卡片上每个按钮、界面上每个被盖住再露出的区域的位置。
- 看过：改动处的静帧，以及成片转场前后的连续帧。
- 听过：做片子的 agent 听不到声音。三个配乐版本是由人听过后选定的，剪接也在听过的那一版里。

## 最弱的地方

- **配乐是从按测量筛出的三首里挑的**，不是从全部候选里听出来的；测量只能排除明显不对的。
- **音效没有被单独确认过**：点击、提示音和打字声的音量是按数值定的。
- **后半仍然是「一句话 + 一个界面」的结构**；卡片那 11 秒里同一句标题一直挂着。
- 拉开看到整个窗口的 1 秒里字只有 16 px，只起建立全貌的作用。

## 和真实产品不完全一致的地方

- 六张卡片只演了按钮按下，没有演点完之后卡片的变化（没有对应的截图）。
- 点「看看」卡片从按钮里长出来、点图表卡片放大成月报页面，是片子的转场，不是产品里真实的跳转方式。
- 首页「刚处理」那一行、月报的渠道表格、成员页的进度条、⌘K 的结果、记得的事、电脑列表，在真实截图里
  本来就在；片子先把它们盖住再露出来，是为了让画面里有事发生。
- 接管那一段把面板左边的话题区域盖成了白色。
- 「回答 Forge」那条待选条是按真实的「审 PR #61」条的样式推出来的。
- 「在右侧打开」在片子里长成了整屏的电脑，真实产品里是右侧面板。
- 搭成员那段里 Ledger 的组合（DeepSeek、你自己的 harness、Notion 和数据库）是演示用的。
- 终端里的命令、开场录屏里的两条闲聊，是为这个故事写的。

## 怎么重新生成

在 `.tmp/promo/`（已装 playwright-core，`CHROME` 指向一个 Chromium）里：

```bash
bun render.mjs --cues && bun ../../promo/audio.mjs cues.json promo.wav
```

```bash
bun render.mjs --frames --workers 8 --sub 4
```

```bash
../../promo/encode.sh ../../promo/out/promo-1080p60.mp4 17
```

英文版：前两条命令加 `--lang en`，第三条输出到 `promo-1080p60-en.mp4`。英文截图在 `.tmp/promo/shots/en/`。
落地页的海报：`bun render.mjs --lang <zh|en> --stills 37.46 --no-cursor`。

换一首曲目：在 `timing/` 里加一份时间表，三条命令前加 `TIMING=<name>`。没选上的两份时间表和对应的曲目
留在 `.tmp/promo/timing-alt/` 和 `.tmp/promo/ext/music/cand/`。
