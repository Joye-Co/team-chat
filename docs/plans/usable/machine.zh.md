# 机器层审计（只读，对照 main 最新代码）

范围：一台电脑怎么接入、活怎么分到电脑、在电脑上怎么跑、凭证和身份、监控、设计和实现对不上的地方。
级别：【不可用】主流程走不通或结果错；【不完整】设计了没做完；【草稿】做了但边界或出错路径没处理、没经真实使用；【小】文案、提示、细节。
标「未核实」的是只读了代码或只搜了关键词、没有实跑的判断。文件里不写具体机器名、id、域名。

已定、不再问的：执行者用个人订阅登录；用户只在 app 里用（不给 shell、不用 Tailscale），接管也在 app 里；bot 出站全开；权限默认全开只拦少数动作；Windows 和 Mac 一致；bot 家目录要持久（11-11）。

## 3. 执行环境

三种环境的差别（现状）：

| | 本机（Mac、不开 VM 的 Linux） | Linux 虚拟机（`[vm]`） | Windows |
| --- | --- | --- | --- |
| 隔离 | 没有。CLI 就是电脑主人这个系统用户 | 每个任务一台虚拟机；但宿主机的 CLI 登录目录和成员家目录读写共享 | 没有，同本机 |
| 家目录 | 电脑主人的 | 每个 AI 成员一个，长期保留，不限大小 | 电脑主人的 |
| 其余磁盘 | 长期 | 任务结束就没了（32 GB） | 长期 |
| 实时查看 | 有 | 有 | 有 |
| 接管 | 暂停，加一个手写进配置的屏幕共享地址 | 只有暂停，人进不去 | 暂停 |
| 审批拦截 | Claude Code 有；Codex 只有提示词 | 同左 | Claude Code 2.1.322 以上才有；Codex 同左 |
| 发布物和更新 | 跟 app | 没有发布物，源码编译加 root 脚本，不自动更新 | 跟 app |

## 4. 凭证和身份

现状：

| 凭证 | 怎么来 | 存在哪 | 谁能用 |
| --- | --- | --- | --- |
| 模型（CLI 订阅登录） | owner 在"订阅账号"里登录，或电脑上本来就登着 | CLI 自己的文件，每台电脑一份 | 这台电脑上所有成员（已定，不动） |

## 7. 需要 Joye 决定的事

只列会改变产品形态的。其余（排队代替失败、10 分钟宽限、家目录 20 GB 上限、通知规则等）按上面的方案直接做。

1. **GitHub 和 git 用谁的身份**（4.1）。选项 A 按交代人、B 按 AI 成员、C 按电脑。建议默认 A，没有交代人时用 B，本机没配时落到 C。还要定：自动触发的活（没人交代）用谁的身份。
2. **谁能加电脑，个人电脑接谁的活**（1.12、3.1、3.8）。
   - 现状：只有 owner 能加，加了以后所有 AI 成员、所有人交代的活都可能落上去。
   - 选项一：成员也能加自己的电脑，默认只接他自己交代的活。
   - 选项二：成员加的电脑由 owner 批准后全队可用。
   - 建议选项一。个人使用时"成员"就是他自己，行为不变。
3. **"接管"做成什么**（3.4）。选项一：在 app 里开终端进到任务的工作目录（新功能，量不小）。选项二：这一版把它明说成"暂停并留言"，不承诺能操作电脑。建议先选项二改名，把选项一排进后面。
4. **密钥归谁**（4.4）。按电脑（现状），还是归团队和个人、自动发到每台有资格的电脑。后者如果要新电脑自动拿到，要么等一台 owner 客户端在线来补发，要么让服务器能转封（等于服务器看得到密钥）。建议归团队和个人，由在线的客户端补发，服务器不碰明文。
5. **个人用户的服务器从哪来**（1.1）。自己部署（现状），还是提供托管、能自己开团队。超出机器层，但它决定"个人使用"的第一步。
