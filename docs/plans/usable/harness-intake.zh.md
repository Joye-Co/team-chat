# harness 层上半段审计：消息进来 → 执行者拿到活 → 结果回到话题

范围：`docs/design/agent-harness.zh.md` 3.1–3.3、4、5 节，对照 main 最新代码（2026-11-12）。只读，没跑真机。
标「未实测」的是按代码推断的行为，标「未核实」的是没读到代码的。

级别：**不可用**＝主流程走不通或结果错｜**不完整**＝设计了没做完｜**草稿**＝做了但边界、错误路径没处理｜**小**＝文案、细节。

先说做得扎实的（不用动）：

- 消息交接不丢不重：和事件同一个事务写 outbox，按消息 id 幂等，失败退避重试（`server/src/bots/room.ts:427-484, 603-647`）。
- run 帧按 (runId, seq) 幂等落库再生效，断线重放不重复（`desk/events.ts:28-61`）。
- 机器人和集成的消息不会启动 run（`room.ts:524-526`）。
- 前台的决定先存后做，重投不重复回复（`desk/front.ts:72-103`）。
- 上下文按字数预算选行，文件、产出、引用、卡片各留一行可按 id 追（`context/render.ts:72-111`）。
- 开发者视图能看到每次 run 实际带的提示词和清单（`context/routes.ts:136-147`）。

## 需要 Joye 定的（只有会改变产品形态的）

- **D1（1.1）话题里有几个 AI 成员时，不带 @ 的跟进给谁。** 「@ 谁给谁」不用定，按 11-09 的方向直接改。建议 a：给最近一次在这个话题干活的成员。
- **D2（1.4）话题里不 @ 时成员回不回。** 建议 b：自己负责的话题里都过前台，闲聊不出声；没配 AI 服务时退到 c。
- **D3（1.5）群聊里同一个成员的第二件事怎么办。** 建议 a：并行，各出各的结果。
- **D4（3.2）私聊要不要默认续接上一个会话。** 建议 a：续接。个人使用几乎全在私聊里。
- 并入别的层：没配 AI 服务时有没有前台（模型层）；电脑离线时排队还是换电脑（机器层）；转交和分出去留不留（多成员协作）。
