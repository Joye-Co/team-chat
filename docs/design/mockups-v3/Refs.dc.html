08

怎么传

协议只加不改：都是新的可选字段和新的方法，不给已有的封闭枚举加值。1.0.x 看不到引用和图块，正文和降级内容照常显示。

引用消息多一个可选的 refs
Message += { refs?: PartRef[] }   // 最多 5 个
{ t: "send", ..., refs?: PartRef[] }

PartRef = {
  messageId: string
  block?: number          // 卡片块的序号
  artifact?: ArtifactRef  // 引用产出时
  part?: { kind: string, key: JSON }
  label: string           // ≤ 120，客户端拼好
  value?: string          // ≤ 200，当时的值
}
服务器检查消息在同一个群、没删；label 和 value 超长就截断。kind 是开放的字符串：row、cell、column、point、bar、series、metric、item、step、line、hunk、region、node、element。不认识的只显示 label。删除原消息时，引用里的 value 一起清空，链接留着。
图消息里的代码块不用改协议；卡片多一种块
// 消息：```mermaid 代码块，客户端自己画

CardBlockV2 += {
  type: "diagram"
  syntax: "mermaid"
  source: string            // ≤ 16 KiB
  title?: string            // ≤ 80
  states?: { [nodeId]: "done" | "current"
             | "waiting" | "failed" }
  waitingOn?: string        // 成员 id
}
给 1.0.x 的 v1 卡片里，服务器把图块换成 { type: "code", lang: "mermaid", text: source }。waiting 只对 waitingOn 那个人显示琥珀色，别人看到灰色的「等某某」。读者不认识的 syntax 当作源码显示。
网页产出桥接多一个方法，页面要声明才能用
Capabilities += { quote: bool }

// 页面 → TeamChat
{ id, method: "quote",
  params: { label, value?, selector? } }

// TeamChat → 页面
{ id, result: { ok: true } }
{ id, error: { code: "no_gesture" } }
只在用户点击后 1 秒内有效，页面不能自己往输入框里塞东西。按住 ⌥ 选元素由 TeamChat 自己做，不需要页面配合；存的是选择器和元素的文字。老页面不声明 quote，什么都不变。
引用和图在话题、单独问、群和产出里共用这一份规格。
